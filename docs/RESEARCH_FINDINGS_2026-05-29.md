## 2. TOKEN CONSOLIDATION ARCHITECTURE

### Proposed Model: 1 Native Token + NFT/Metadata Layer

```
CXN Native Token (Fungible)
├── Gas fees for protocol operations
├── Network effects / liquidity pool
├── Staking security / validator bonds
└── Core economic gravity

NFT / Semi-Fungible Layer (ERC-1155 pattern)
├── Creator economy roles & memberships
├── Brand credentials & reputation scores
├── Utility rights (governance weight, revenue share)
├── Achievement / contribution attestations
└── Multi-dimensional identity (NOT money)
```

### Why ERC-1155 Pattern
- Single contract manages both fungible + non-fungible tokens
- Batch operations = gas efficient multi-asset transfers
- Semi-fungibility: same token ID can represent multiple identical units
- Metadata on IPFS/Arweave for functional diversity without token proliferation
- Battle-tested: Enjin, OpenSea, The Sandbox, Decentral Games

### Research Gaps (Flagged)
- Stacks-native SFT/SIP support in Clarity
- SIP-compatible multi-token standard availability
- Metadata storage strategy: IPFS vs Arweave vs Gaia hub
