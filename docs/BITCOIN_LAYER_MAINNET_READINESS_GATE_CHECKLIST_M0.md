## Status

Canonical shared M0 gate checklist for [#662](https://github.com/Conxian/conxian-business/issues/662), decomposed from [#638](https://github.com/Conxian/conxian-business/issues/638).

## Purpose

Freeze one shared definition of "mainnet-ready" for Bitcoin mainnet, Lightning, and Stacks with explicit separation between:

- implemented production-path evidence
- simulation evidence

## Canonical Lightning boundary decision (locked)

Lightning is **gateway-first / gateway-owned adapter surface**.

Release-gate interpretation:

- Lightning adapter implementation ownership is `conxian-gateway`.
- Release readiness fails if Lightning production-path evidence depends on adapter logic outside the gateway-owned surface.

## Evidence classes (must be explicit)

### 1) Implemented production-path evidence

Evidence generated by real production-boundary code paths (not mocks), traceable to immutable identifiers (commit SHA, run ID, txid, artifact hash).

### 2) Simulation evidence

Evidence generated by simulation, replay, or preflight harnesses (including mocked dependencies and deterministic dry-runs).

Rule: simulation evidence is required for confidence and regression safety, but does **not** replace missing production-path evidence for release-blocking capabilities.

## Shared checklist: implemented production-path evidence (release-blocking)

The following capabilities must have production-path evidence for **each layer** (Bitcoin mainnet, Lightning, Stacks):

| Capability | Required implemented production-path evidence |
| --- | --- |
| Adapter | Gateway-owned adapter path executes end-to-end through real provider/node boundary; fail-closed negative path included. |
| Signer | `conxius-enclave-sdk` signer path executes on real transaction/invoice intent with policy checks and audit traceability. |
| Verification | `lib-conxian-core` verification checks execute in the production path and settle-state checks are evidenced via gateway/nexus integration surfaces. |
| Simulation | Simulation APIs/tools are exposed by production code and enforce production policy constraints (no bypass-only simulation path). |
| Reference example | `conxius-wallet` demonstrates one canonical flow using production-boundary interfaces for the layer. |

Layer-specific production blockers:

- **Bitcoin mainnet:** adapter completeness closed; signer-controlled tx flow validated; verify/settle evidence complete; no simulated-only production path.
- **Lightning:** gateway-first boundary enforced; signer + verification production path evidenced; release integration suite includes Lightning path.
- **Stacks:** signer-path standardization complete; verification evidence complete; deployment principal validation complete; fail-closed behavior evidenced.

## Shared checklist: simulation evidence (required, non-blocking unless escalated)

Simulation evidence must be recorded separately from production evidence for each layer/capability:

| Capability | Required simulation evidence |
| --- | --- |
| Adapter | Deterministic adapter replay or harness run that exercises expected and degraded states. |
| Signer | Dry-run/harness coverage for authorization, rejection, and recovery edge paths. |
| Verification | Deterministic fixtures for pass/fail vectors (destination, network, amount/fee/policy mismatches). |
| Simulation | Scenario matrix including at least one degraded-mode and one recovery path. |
| Reference example | Scripted/demo replay that can be re-run by reviewers without privileged credentials. |

## Release blockers vs non-blockers (explicit)

### Release blockers

1. Missing implemented production-path evidence for **adapter**, **signer**, or **verification** on any of the three layers.
2. Lightning path violates or bypasses the **gateway-first / gateway-owned adapter surface** decision.
3. Layer-specific production requirements (above) are incomplete for the release target.
4. Recovery evidence/runbook for the release target layer is absent for required failure modes.
5. Any release claim that relies only on simulation evidence for production-critical paths.

### Non-blockers

1. Additional simulation scenario expansion beyond the required baseline (when required production evidence is complete).
2. Additional reference examples beyond one canonical `conxius-wallet` flow per layer.
3. Documentation refinements that do not alter ownership, boundary, or release-gate definitions.

## Decision-use rule

A layer is "mainnet-ready" only when release blockers are closed with production-path evidence and simulation evidence is separately documented.
