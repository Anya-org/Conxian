# Akash Autonomous Deployment Specification (BaaP v2.1)
**Date:** April 18, 2026
**Subject:** Transitioning Conxian Sovereign Nodes to Akash Network

## 1. Objective
Enable resilient, decentralized deployment pathways for Conxian Sovereign Node components using Akash-aligned infrastructure.

## 2. Public-safe deployment outline
The public architecture intent remains:

- Deploy Nexus, Gateway, and UI services in a decentralized runtime environment.
- Preserve persistent-state and data-integrity guarantees across redeployments.
- Keep custody-sensitive runtime configuration in restricted operational systems.

### Redaction notice
Detailed service templates, principal/address bindings, image/version pinning strategy, relay endpoints, resource bids, and deployment profiles are intentionally maintained in private operations records.

## 3. Persistent state posture
- State persistence and reconciliation requirements remain mandatory.
- Environment-specific connection details are controlled in private infrastructure records.

## 4. Implementation path (public-safe)
1. Maintain reproducible container build and release discipline.
2. Enforce controlled secret and key material handling outside public repositories.
3. Operate deployment workflows through governed custody and approval controls.
